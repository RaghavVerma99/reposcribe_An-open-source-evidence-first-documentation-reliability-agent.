# Audit findings — 2026-10-26

RepoScribe has been audited twice against the spec in `SPEC.md` and the shipped code. This document is the honest inventory: what was fixed, what is open, and where. The latest tag is **v0.3.0**, which closed the five items further down.

The Tag column below maps each item to the release that either fixed it or marked it explicit-open. Contributors and reviewers may trust the `Resolved in` column.

## Resolved in v0.2.0

These were the four high-severity honesty bugs found in the first audit, plus `B2` from the second audit, plus a structural API addition needed to validate the fixes.

| ID | One-line summary | Resolved in |
|---|---|---|
| `#1` | Patch `V-3` validator compared by `finding.id`; a patch that changed the subject slipped past validation. | v0.2.0 — `Finding.subject_key` field added; V-3 now compares by `(check_id, subject_key)` |
| `#2` | Patch generator rewrote only the path on a method+path drift, producing routes that existed nowhere (e.g. `DELETE → DELETE /api/v2/users`) and falsely reporting "both method and path changed". | v0.2.0 — generator refuses method+path combined rewrites and reports the truth in limitations |
| `#3` | `/search` and Q&A citations echoed secret-shaped content from ordinary files (e.g. `DATABASE_PASSWORD=hunter2`). | v0.2.0 — `Chunk.text` runs through `redact()` before being returned |
| `#4` | OpenAPI-only repositories audited "clean" with no caveat: JSON was parsed but routes were dropped (no `index.docs` entry), YAML was never read. | v0.2.0 — supports YAML via PyYAML; `openapi.{json,yaml,yml}` always emit findings with proper evidence |
| `B2` | Backend allowed `POST /patches` for dismissed/resolved findings; UI prevented with `disabled` but backed off on the request. | v0.2.0 — `PatchService.create()` returns `patch_not_available` (422) |
| New field | `Finding.subject_key` is a stable identifier of the underlying defect, mirrored in the frontend `Finding` type. | v0.2.0 |

## Open at v0.3.0 (next round)

Each row is **Severity | Where | Category | Summary | Suggested fix**.

### Backend correctness

- **`#6` SPA deep-link returns JSON 404** — Severity: Medium | `backend/app/main.py:94` (`StaticFiles(html=True)`) + `BrowserRouter` | Single-service mode 404s on any deep route. Fix: serve `index.html` for any non-API, non-asset path that doesn't match a static file. Or: middleware fallback that returns the shell HTML for `text/html` Accept and the 404 envelope for `application/json`.
- **`#7` CHK-02 false positives on "create this file" instructions** — Severity: Medium | `backend/app/analyzers/docs_references.py:31` | Every inline-code span in any doc triggers the check, including doc text that says "Create `myapp.py`". Fix: only scan spans in setup/configuration/installation context (heading + next ~20 lines), or weight spans less aggressively when adjacent text is instructional.
- **`#8` Landing "Retry" opens the sample repository** — Severity: Medium | `frontend/src/features/repositories/LandingPage.tsx` | After an upload error, the `Retry` button calls `openSample()` and silently creates the bundled repo. Fix: track the last-intent (`sample` vs `upload`) and re-run that.
- **`#9` No per-repository audit concurrency guard** — Severity: Medium | `backend/app/api/audits.py`, `audit_service.py` | Two concurrent `POST /audits` can race on `state.findings/audits`; the `audit_in_progress` error code is defined but never raised. Fix: per-`repository_id` `asyncio.Lock` keyed by state; reject with 409.
- **`#10` First audit erases `state.limitations`** — Severity: Medium | `repository_service.py:119` vs `audit_service.py:89` | `state.limitations` is written by `reindex` (scan skips) and overwritten by `AuditService.run` (check caveats). The Overview field is labelled "Scan limitations" but shows audit caveats once any audit ran. Fix: separate the two into `state.scan_limitations` and `state.check_limitations`, expose both.
- **`#11` No request logging (OPS-02)** — Severity: Medium | `backend/app/main.py` middleware | Request IDs are minted and returned in `X-Request-ID` but never logged. Fix: a small `logging` module + one `INFO` line per request (`request_id, route, duration_ms, status`). Optional basic log to a JSON file when `WORKSPACE_PERSIST_LOGS=1` for incident review.
- **`#13` Manifest lacks excluded/reason (ING-06)** — Severity: Low | `schemas/models.py`, `security.iter_files` | Excluded files are dropped before the manifest, so reviewers cannot tell why a file was skipped. Fix: keep excluded files in the manifest with a `excluded: true` and `reason` field, then surface them on demand.
- **`#14` `RouteInfo.prefix_resolved` is always `true`** — Severity: Low | `analyzers/common.py` | Unresolved prefixes silently drop routes; the field is then meaningless on the API. Fix: surface `false` on the per-route level when a variable router prefix could not be resolved.
- **`#15` Duplicate constants drift** — Severity: Low | `python_symbols.py` vs `patch_service.py` | `STDLIB_ROOTS` differs between `python_symbols.py` (filtering CHK-05) and `patch_service.py:_introduced_issues` (filtering V-5). Fix: a single canonical source.
- **`#18` Severity deviates from the catalog** — Severity: Low | `markdown_links.py:54`, `readme_checklist.py:92` | Broken-anchor emits `low` (catalog says `medium`); README API-docs checklist emits `medium` (catalog says `info`). Fix: align with §8.1.
- **`#19` Workspace TTL is creation-based** — Severity: Low | `store.py:_sweep_locked` | An active session loses its workspace 2 h after `POST /repositories`, even mid-flow. Fix: track `last_accessed_at`; sweep on `now - last_accessed > ttl`.
- **`#20` Manifest `sha256`/`secret` build is dead** — Severity: Low | `repository_service.py` | Computed and stored on `ManifestEntry` but never exposed and never used. Fix: either expose it on `GET /repositories/{id}/manifest` or remove the fields.

### Endpoint / contract

- **`B7` No `ETag` / `If-Match` on `PATCH /findings/{id}`** — Severity: Low | `backend/app/api/findings.py` | Concurrent PATCHes overwrite one another silently. Fix: `If-Match: <finding.id>` (using the existing stable id) and respond with 412 on mismatch.
- **`B8` Frontend `CHECK_LABELS` duplicates `SPEC.md §8`** — Severity: Low | `frontend/src/lib/format.ts` | Labels are hardcoded. Fix: serve `/api/v1/checks` and the UI consumes it.
- **`B9` `findings_total` includes `resolved` forever** — Severity: Low | `audit_service.py` | The headline number grows monotonically across audits. Fix: optionally expose a `findings_active_total` excluding resolved/dismissed (`/findings?status=active` or a derived metric).
- **`B10` Sample id `fastapi-users` is hardcoded** — Severity: Low | `repository_service.py:43` | Adding a new sample requires a code change. Fix: a directory of samples listed at startup.
- **`B11` No global request-body size limit** — Severity: Low | `backend/app/main.py` middleware | Only the upload endpoint enforces a size cap. Fix: middleware-level `Content-Length` guard (or streaming byte counter) with a small default.
