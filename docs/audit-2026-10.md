# Audit findings — 2026-10-26

RepoScribe has been audited twice against the spec in `SPEC.md` and the working code. This document records the 2026-10-26 audit round: what was fixed, what is open, and where. No git tag exists; the `0.2.0` and `0.3.0` labels below are development milestone labels, not published releases. A later verification pass is recorded in [`audit-2026-10-verification.md`](audit-2026-10-verification.md).

The Resolved-in column below maps each item to the change that fixed it. Contributors and reviewers may trust that column; the open list is the remaining work.

## Resolved in the 0.2.0 milestone

These were the four high-severity honesty bugs found in the first audit, plus `B2` from the second audit, plus a structural API addition needed to validate the fixes.

| ID | One-line summary | Resolved in |
|---|---|---|
| `#1` | Patch `V-3` validator compared by `finding.id`; a patch that changed the subject slipped past validation. | 0.2.0 — `Finding.subject_key` field added; V-3 now compares by `(check_id, subject_key)` |
| `#2` | Patch generator rewrote only the path on a method+path drift, producing routes that existed nowhere (e.g. `DELETE → DELETE /api/v2/users`) and falsely reporting "both method and path changed". | 0.2.0 — generator refuses method+path combined rewrites and reports the truth in limitations |
| `#3` | `/search` and Q&A citations echoed secret-shaped content from ordinary files (e.g. `DATABASE_PASSWORD=hunter2`). | 0.2.0 — `Chunk.text` runs through `redact()` before being returned |
| `#4` | OpenAPI-only repositories audited "clean" with no caveat: JSON was parsed but routes were dropped (no `index.docs` entry), YAML was never read. | 0.2.0 — supports YAML via PyYAML; `openapi.{json,yaml,yml}` always emit findings with proper evidence |
| `B2` | Backend allowed `POST /patches` for dismissed/resolved findings; UI prevented with `disabled` but backed off on the request. | 0.2.0 — `PatchService.create()` returns `patch_not_available` (422) |
| New field | `Finding.subject_key` is a stable identifier of the underlying defect, mirrored in the frontend `Finding` type. | 0.2.0 |

## Fixed in the 0.3.0 working tree (third round: abuse controls)

The second round closed honesty defects in what the tool reports. This round closes ways to abuse the running
service itself. Order: request bodies, response bounds, run time, session identity.

| ID | One-line summary | Where | Fixed in |
|---|---|---|---|
| `D1` | Only the upload endpoint enforced a size cap; every other route would buffer an arbitrarily large JSON body (open item B11). | `backend/app/main.py` middleware, `schemas/models.py` | 0.3.0 - a global Content-Length gate returns 413 for non-multipart bodies over `MAX_REQUEST_BODY_MB` (default 1 MB), and `AuditRequest.check_ids` is capped at the schema level |
| `D2` | Five of six analyzers could return unbounded findings; a repository with thousands of broken links produced an unbounded audit response. | `backend/app/analyzers/*.py` | 0.3.0 - every check caps at 100 findings (CHK-04 keeps its tighter 25) and states the cap in limitations |
| `D3` | An audit had no time budget; a pathological repository could hold a request open indefinitely (the threat model claimed this control existed — it did not). | `services/audit_service.py`, analyzers | 0.3.0 - `AUDIT_TIMEOUT_SECONDS` (default 60); checks that do not finish are reported as skipped |
| `D4` | A check stopped by the time budget would have marked every finding it never reached as `resolved`. | `services/audit_service.py` | 0.3.0 - an incomplete check is recorded as skipped, so no finding can be resolved by a check that did not run to completion |
| `D5` | The session cookie was a bare id a client could choose, so a planted cookie fixed a victim onto a session the attacker knew. | `core/security.py`, `main.py` | 0.3.0 - the cookie value is `<id>.<hmac>` signed with `SESSION_SECRET` (or a per-process secret); a forged value is ignored and a fresh session is issued |

## Fixed in the 0.3.0 working tree (second round: correctness and hardening)

These were found by reading the code and by runtime probes, not by the original spec audit. Each one is a
defect in the tool's own promise: never report a defect that is not there, never miss one that is.

| ID | One-line summary | Where | Fixed in |
|---|---|---|---|
| `C1` | A route patch rewrote **every** line containing the documented path, so fixing `GET /api/users` also rewrote the neighbouring `DELETE /api/users/{user_id}` row into a route the code never defines. | `backend/app/integrations/local_demo.py` | 0.3.0 - a line is only rewritten when it contains both the documented method and the documented path |
| `C2` | Validation compared only the originating finding, so a draft that fixed its own claim while inventing another route passed all six steps. | `backend/app/services/patch_service.py` | 0.3.0 - V-3 compares the whole finding set before and after the patch and fails on any newly introduced finding |
| `C3` | Validation failed on links that were already broken before the patch, so a sound repair could never validate. | `backend/app/services/patch_service.py` | 0.3.0 - V-4 counts only links the patch adds or breaks; pre-existing ones are reported but not counted |
| `C4` | The rate limit was keyed on the unsigned session cookie, so clearing the cookie reset the budget. 140 requests with a fresh cookie each produced no 429 at all. | `backend/app/main.py` | 0.3.0 - the limit is keyed on the client address, and idle buckets are swept |
| `C5` | The rate-limit bucket map grew without bound; one entry per session was never removed. | `backend/app/main.py` | 0.3.0 - buckets are swept, and the number of tracked clients is capped |
| `C6` | A router mounted from another module (`app.include_router(router, prefix="/api")`) was compared at its local path, so a correctly documented route was reported as missing. | `backend/app/analyzers/common.py` | 0.3.0 - mount prefixes from other modules are applied to the routes of the target module |
| `C7` | Any file that merely included a router was marked as having an unresolved prefix, which downgraded **every** route finding in the repository to `insufficient_evidence`. | `backend/app/analyzers/common.py` | 0.3.0 - only a genuinely unresolvable prefix marks the repository as unresolved |
| `C8` | A nested router (`router.include_router(sub)`) did not inherit the parent router's prefix. | `backend/app/analyzers/common.py` | 0.3.0 - parent prefixes are combined with the child prefix |
| `C9` | A citation without line numbers was always rejected, and the clamped range could end up inverted. | `backend/app/services/question_service.py` | 0.3.0 - a citation without lines is matched on its path, and ranges are clamped to the retrieved excerpt |
| `C10` | A download filename was taken verbatim from the repository path, so a quote or a non-ASCII name produced a malformed `Content-Disposition` header. | `backend/app/services/export_service.py` | 0.3.0 - filenames are reduced to a safe ASCII form |
| `C11` | The workspace-writability probe was cached for the whole process lifetime, so a workspace that became unwritable was still reported as healthy. | `backend/app/api/health.py` | 0.3.0 - the probe is cached for a short window and re-checked afterwards |
| `C12` | Indexing decoded every JSON and YAML file in the repository although only OpenAPI documents are parsed, and walked the tree three times. | `backend/app/analyzers/common.py` | 0.3.0 - only files that can be an OpenAPI document are read, and the tree is walked once |
| `C13` | The frontend parsed every response body with `JSON.parse`, so an HTML error page from a proxy crashed the UI with a `SyntaxError` instead of showing the real status. | `frontend/src/lib/api.ts` | 0.3.0 - a non-JSON body is reported as an `invalid_response` error |
| `C14` | A symbol patch replaced the first occurrence of the symbol name anywhere in the token, which could rewrite the module part of the name. | `backend/app/integrations/local_demo.py` | 0.3.0 - only the last segment is replaced |

## Open in the 0.3.0 working tree (next round)

Each row is **Severity | Where | Category | Summary | Suggested fix**.

### Backend correctness

- **`#13` Manifest lacks excluded/reason (ING-06)** — Severity: Low | `backend/app/schemas/models.py`, `core/security.iter_files` | Excluded files are dropped before the manifest, so reviewers cannot tell why a file was skipped. Fix: keep excluded files in the manifest with an `excluded: true` and `reason` field, then surface them on demand.
- **`#14` The route list could be silently incomplete** - Severity: Low | `backend/app/schemas/models.py`, `services/repository_service.py` | **Closed in the correctness round.** Routes with an unresolvable prefix are dropped, so the per-route `prefix_resolved` flag was always `true` and the API never said the list was incomplete. The overview now exposes `routes_prefix_unresolved`, the UI states that the route list is incomplete, and the root cause (routers mounted from another module) is resolved rather than merely reported. |

### Endpoint / contract

- **`B11` No global request-body size limit** — **Closed in the abuse-control round (`D1`).**

- **`B7` No `ETag` / `If-Match` on `PATCH /findings/{id}`** — Severity: Low | `backend/app/api/findings.py` | Concurrent PATCHes overwrite one another silently. Fix: `If-Match: <finding.id>` (using the existing stable id) and respond with 412 on mismatch.
- **`B8` Frontend `CHECK_LABELS` duplicates `SPEC.md §8`** — Severity: Low | `frontend/src/lib/format.ts` | Labels are hardcoded. Fix: serve `/api/v1/checks` and have the UI consume it.
- **`B9` `findings_total` includes `resolved` forever** — Severity: Low | `backend/app/services/audit_service.py` | The headline number grows monotonically across audits. Fix: optionally expose a `findings_active_total` excluding resolved/dismissed (`/findings?status=active` or a derived metric).
- **`B10` Sample id `fastapi-users` is hardcoded** — Severity: Low | `backend/app/services/repository_service.py` | Adding a new sample requires a code change. Fix: a directory of samples listed at startup.
